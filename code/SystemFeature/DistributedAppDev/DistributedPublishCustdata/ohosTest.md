# 分布式设备发现自定义数据测试用例归档

本示例为命令行 native C 程序，测试用例均为手动执行，需要两台已完成分布式组网并相互在线的 OpenHarmony 设备，分别运行同一份 `disc_coap_custdata_sample` 可执行文件，且两端软总线均开启 `DSOFTBUS_FEATURE_DISC_COAP_CUSTDATA` 特性。

## 用例表

| 测试功能 | 预置条件 | 输入 | 预期输出 | 是否自动 | 测试结果 |
| -------- | -------- | ---- | -------- | -------- | -------- |
| 启动程序并显示本机信息 | 可执行文件已部署到两台已组网设备 | 运行程序 | 显示角色菜单和掩码后的本机设备名（如 `DEV#ab**cd`），含"发布端（等待被发现）"和"发现端（发现附近设备）"两个角色入口，输入 `2` 打印 `BYE` 退出 | 否 | Pass |
| 发布端发布设备并进入监听 | 设备 A 已运行程序 | 角色菜单输入 `0` 进入发布端菜单，再输入 `0` 发布设备 | 打印 `PublishLNN payloadLen=41` 和默认标识，随后打印 `Listen thread: 正在监听`，发布端持续等待发现端连接；输入 `3` 状态显示 `publish active=YES` | 否 | Pass |
| custData 匹配与不匹配过滤 | 设备 A 已发布（默认标识），设备 B 已运行程序 | 设备 B 角色菜单输入 `1`，再输入 `0` 开始寻找设备；随后输入 `2` 把期望特征改为与发布端不一致的内容 | 默认标识一致时打印 `custData match expected payload, add to discovered list`，设备 A 进入发现列表；标识不一致时打印 `custData mismatch`，设备 A 从列表移除，输入 `5` 查看状态列表中无设备 | 否 | Pass |
| 连接白名单设备并收发消息 | 设备 A 已发布且设备 B 发现列表中已有设备 A | 设备 B 输入 `3` 连接所有找到的设备，成功后输入 `4` 发送消息 | 设备 B 打印 `Bind 成功` 和 `[REF-BIND-OK]`，发送后打印 `[SEND]` 且 `ret=0`，统计为"成功 1"；设备 A 打印 `[PUB-LISTEN-BIND]` 和 `[PUB-LISTEN-RECV]`，数据内容为"hello,第N条消息(特征:...)" | 否 | Pass |
| 修改标识后重新生效 | 设备 A 处于发布菜单，设备 B 已发现设备 A | 设备 A 输入 `2` 设置新标识后停止并重新发布；设备 B 输入 `2` 同步修改期望特征后重新寻找 | 设备 A 打印 `payload set` 且重新发布成功；设备 B 期望特征修改为一致时可再次发现设备 A，修改为不一致时设备 A 从发现列表移除 | 否 | Pass |
| 断链与停止发现清理 | 设备 A 与设备 B 已建立连接 | 设备 A 输入 `1` 停止发布；设备 B 重新连接后输入 `1` 停止寻找 | 停止发布时设备 B 打印 `[REF-BIND-SHUTDOWN]` 并从发现列表移除设备；停止发现时发现列表清空且已建立的连接全部关闭，两端无残留连接 | 否 | Pass |
