# 分布式数据传输测试用例归档

本示例为命令行 native C 程序，测试用例均为手动执行，需要两台已完成分布式组网并相互在线的 OpenHarmony 设备，分别运行同一份 `video_stream_sample` 可执行文件。

## 用例表

| 测试功能 | 预置条件 | 输入 | 预期输出 | 是否自动 | 测试结果 |
| -------- | -------- | ---- | -------- | -------- | -------- |
| 启动程序并查看在线设备 | 可执行文件已部署到两台已组网设备 | 运行程序，角色菜单输入 `2` | 显示角色菜单和掩码后的本机设备名（如 `DEV#ab**cd`），并列出对端在线设备 | 否 | Pass |
| Listen 端进入监听 | 设备 B 已运行程序 | 角色菜单输入 `1`，选择传输方式 | 打印 `Socket() create succ` 和 `监听 socket=x, 等待投屏请求...`，阻塞等待投屏 | 否 | Pass |
| 三种数据类型投屏收发 | 设备 B 已处于监听状态 | 设备 A 输入 `0` 发起投屏，依次选择 MESSAGE（`1`）、BYTES（`2`）、RAW_STREAM（`3`），设备 B 协商时均输入 `1` 接受 | 设备 A `Bind ret=0` 并持续打印 `[SEND-MESSAGE]`/`[SEND-BYTES]`/`[SEND-STREAM]` 且 `ret=0`；设备 B 对应打印 `[RECV-MESSAGE]`/`[RECV-BYTES]`/`[RECV-STREAM]`，帧数递增，数据为 `frame#NNN:<掩码UUID>` | 否 | Pass |
| Listen 端拒绝投屏 | 设备 B 已处于监听状态 | 设备 A 发起投屏，设备 B 协商提示输入 `0` 拒绝 | 设备 B 保持监听；设备 A `Bind()` 返回失败并打印投屏失败，投屏列表无新增项 | 否 | Pass |
| 断开投屏与异常断链清理 | 设备 A 与设备 B 投屏中 | 设备 A 菜单输入 `1` 断开设备 B；再次投屏后由设备 B 菜单输入 `2` 退出 | 主动断开时设备 A 打印 `断开投屏` 及累计统计；两种方式下设备 B/A 均收到 `OnShutdown`，对端自动从投屏列表移除 | 否 | Pass |
| Listen 端发送数据与状态查看 | 两端已建立投屏 | 设备 B 接收菜单输入 `1` 查看状态，再输入 `0` 发送数据 | 状态显示 `投屏中, 对端=DEV#xxxx**xxxx`；发送返回 `ret=0`，设备 A 收到内容为 `listenSend_N` 的数据 | 否 | Pass |
