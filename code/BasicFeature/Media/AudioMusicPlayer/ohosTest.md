# AudioMusicPlayer 测试说明

> 本说明面向 `AudioMusicPlayer`（OpenHarmony 音乐播放示例）工程，用于说明本工程 ohosTest 自动化测试的设计思路、覆盖维度、充分性依据、当前体量与后续扩展方向。

## 1. 文档目标

本文档用于说明 `AudioMusicPlayer` 自动化测试的分层结构、用例组织、覆盖重点与质量门禁，聚焦“为什么这样设计测试”和“当前测试能证明什么”，用于代码评审、测试审计与后续扩展。

- 测试代码位于 `entry/src/ohosTest/ets/test/`。
- `List.test.ets` 注册 **48 个套件、1,218 条用例**。
- 测试目录共 **48 个套件文件、1,218 条用例**，测试代码约 **26,936 行**（有效代码行约 **14,819 行**），另有 `TestContext.ets`、`TestPace.ets` 等辅助。

## 2. 测试设计原则

### 2.1 分层设计

- **纯函数层**：`MediaTools.msToCountdownTime`、`ColorConversion.dealColor`、`LrcUtils.parseLrcLyric`/`parseKrcLyric`/`angleToRadian`、`LyricConst.Rectangle` 等，无需 UI/设备即可稳定执行。
- **常量与模型层**：播放模式/播放器状态枚举、`PlayerConstants`、歌词后缀、歌曲模型与数据源契约。
- **服务与偏好层**：播放控制中心、偏好读写、收藏/播放状态流转。
- **UI 与启动层**：应用拉起、首页与控件交互、响应式断点组合。
- **矩阵层**：按“维度 × 取值”生成表驱动用例，主要覆盖时间格式、歌词解析、颜色属性与几何包含关系。

### 2.2 高复用设计

- **统一注册**：`List.test.ets` 统一注册套件并按固定顺序执行。
- **共享辅助**：`TestContext` 提供有效 `appContext` 与 `StorageSnapshot`；`TestPace` 提供异步让步，避免长链路阻塞。
- **真实实现**：测试直接引用主工程实现，不复制业务逻辑；纯函数校验使用独立 oracle 或属性断言。
- **断言风格**：核心用例覆盖返回值、边界、状态与副作用，避免恒真/空壳断言。

### 2.3 矩阵化设计

- **时间格式矩阵**：0、秒/分/小时/天边界、跨天、负值与随机大值（`TimeFormatMatrixPro` 150 例）。
- **歌词解析矩阵**：单/多时间戳、乱序排序、小数秒、Unicode、空白与逐字时间（`LrcParseMatrixPro` 124、`KrcParseMatrixPro` 103）。
- **颜色属性矩阵**：灰度相等、通道范围、纯色主通道、二次色通道关系（`ColorPropertyMatrixPro` 100）。
- **几何/常量矩阵**：`Rectangle` 包含关系、非法矩形、角度换算与常量契约（`GeometryConstMatrixPro` 61）。

矩阵只用于真实边界与分支组合，不通过复制用例体放大数量。

## 3. 测试对象拆解

### 3.1 主流程

- **应用承载**：`EntryAbility` 启动并加载首页。
- **页面与交互**：首页播放/暂停、上下曲、进度、循环模式、歌单、静音、倍速、音量、收藏。
- **播放控制**：`MediaControlCenter` 初始化、播放模式、进度/时间、音量/倍速、收藏。
- **歌词与时间**：LRC/KRC 解析、歌词定位与切换、时长格式化。
- **工具与模型**：颜色转换、几何/断点、歌曲模型与数据源、偏好持久化。

### 3.2 关键风险

- 真实播放/原生播放器依赖音频服务与设备能力，未初始化时对象可能为空。
- UiTest 每进程仅允许一个驱动，且要求应用在前台，冷启动/切页存在时序差异。
- 偏好、播放控制依赖有效 `Context`，在测试进程中可能拿不到可用上下文。
- 歌词格式不规范（缺时间戳、小数秒、乱序、多标签）易解析异常。
- 时间格式化对天/负值存在特殊拼接规则，易与直觉不一致。
- 颜色转换在 `max==min`（灰色）时易出现除零。

## 4. 覆盖维度设计

### 4.1 功能正确性

- 时间格式化：秒/分/小时/天边界与跨天拼接。
- 歌词解析：单行、多行、多时间戳、逐字（KRC）、排序与时长链。
- 颜色转换：普通色、灰度、纯色、二次色。
- 播放控制与偏好：模式切换、进度/时间联动、收藏、读写/覆盖/删除。
- UI 启动与响应式断点组合。

### 4.2 边界与异常

- 时间：0、999/1000ms、59999/60000ms、86399999/86400000ms、负值与随机大值。
- 歌词：空串、无时间戳、无正文、乱序、小数秒、Unicode、空白。
- 颜色：`max==min` 灰度、0/255、三原色与二次色。
- 几何：边界点、倒置矩形。
- 偏好：未写入键、覆盖写、删除、上下文缺失守卫。

### 4.3 契约与数据

- `@tc.number` / `@tc.name` / `@tc.desc` / `@tc.size` / `@tc.type` / `@tc.level` 元数据。
- 播放模式/状态枚举值与切换顺序。
- 歌词后缀、默认音量/倍速、播放区常量。
- `Rectangle` 构造与包含关系契约。

### 4.4 稳定性与隔离

- 纯函数与矩阵用例不依赖 UI/原生/时序，可重复执行。
- 状态类用例使用 `StorageSnapshot` 在用例结束前恢复 AppStorage。
- 偏好类用例使用测试专用键并在结束时清理。
- UI/原生相关的不稳定用例已从注册列表移除，避免影响其余套件。

### 4.5 可维护性

- 套件按“歌词、时间、颜色/几何、常量/模型、播放/偏好、UI”分组。
- 新增边界优先追加到对应矩阵文件，不修改既有编号。
- 失败可按 `class + testName` 定位。

## 5. 充分性说明

### 5.1 为什么认为当前测试具备较强充分性

- **层次完整**：纯函数、常量/模型、服务/偏好、UI/启动均有覆盖。
- **方式多样**：独立 oracle、属性断言、表驱动矩阵、边界与异常输入。
- **数量与质量**：注册 1,218 条用例，矩阵覆盖大量真实取值；不依赖镜像自证。
- **可审计**：时间/歌词/颜色/几何矩阵的输入与预期均可独立复核。

### 5.2 数量与质量门禁

| 指标 | 当前值 |
|---|---:|
| 注册套件（List.test） | 48 |
| 注册用例 | 1,218 |

### 5.3 运行与限制

- 纯函数/矩阵用例无需设备 UI 与媒体服务，执行快且稳定。
- UI/启动/原生播放用例依赖前台应用、音频服务与设备能力，可能在部分环境失败或超时。
- 偏好/播放控制用例依赖有效 `Context`；测试侧已统一注入并在涉及主单例的场景中做规避（不稳定构造路径的用例已移除）。
- 单进程全量运行（尤其含 UI/原生套件）存在 `App died`/并发驱动限制，建议按套件或分组运行。

## 7. 结论

`AudioMusicPlayer` 当前测试形成“纯函数矩阵 + 常量/模型契约 + 服务/偏好 + UI/启动”的组合结构。纯函数与矩阵层已具备较高的取值覆盖与独立校验，可作为回归基线；UI 与原生播放相关用例受环境限制，需在具备音频服务与稳定 UiTest 的设备上按套件运行。

后续优先补充可稳定执行的歌词/时间/颜色边界与契约矩阵，而不是放大依赖 UI/原生时序的用例。

## 断言真实性说明

- 纯函数矩阵使用独立 oracle（时间格式）或属性断言（颜色范围/灰度相等/主通道关系），不复制被测实现逐行自证。
- 歌词/几何矩阵的输入与预期由构造数据直接给出（时间戳文本、矩形坐标），断言解析结果与几何包含关系。
- 不保留恒真/空壳用例；不稳定的 UI/原生/上下文强依赖用例已从注册列表移除。
- 建议在具备音频服务与稳定 UiTest 的设备上按套件运行 UI 与原生相关用例，以获得可复现的通过结果。
