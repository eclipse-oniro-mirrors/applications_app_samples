# AVCodec代码与文档编写约定

本约定适用于生产代码、测试、代码注释、README和测试说明。修改前同时核对仓库的[CodeCommitChecklist.md](../../../../../CodeCommitChecklist.md)，提交前检查本次差异。

## 函数职责与长度

- 按`G.FUD.05`和C++超大函数规则检查函数，函数体有效代码不超过50行，空行和注释不计入。测试函数和lambda同样适用。
- 超限时按初始化、执行、状态转换、验证和清理等职责拆分，保留原有调用顺序、同步边界和失败处理。
- 不通过压缩多条语句、删除说明性注释或关闭检查规避行数限制。拆分后的函数应能从名称看出用途。

## C++lambda捕获

- 按`G.RES.06-CPP`显式列出lambda使用的变量，禁止使用默认值捕获或默认引用捕获。
- 只捕获实际使用的对象；跨线程或异步执行时，确认被引用对象在回调结束前始终有效。
- 引用共享测试上下文时，所有工作线程必须在上下文销毁前退出；重构不能缩短锁或资源的有效期。

## ArkTS成员访问范围

- 按`G.EXT.01`为类属性显式声明`public`、`protected`或`private`，不依赖默认访问范围。
- 对外使用的数据字段声明为`public`，实现细节声明为`private`；接口字段不添加类成员访问修饰符。
- 新增或调整字段时，同时检查同一类中用途相同的字段，避免只修复报告中的一行。

## 文档、注释与术语

- 按`WordsTool.doc1`和`WordsTool.249`使用准确、常见的行业术语，保留API、错误码、用例编号和实际验证范围。
- 写明操作对象和执行阶段，例如“初始加载”“后续重读”“剩余监听”，避免含糊指代和缺少边界的描述。
- 错误处理明确条件，例如“非EBADF关闭错误”，不把不同错误分支笼统合并；序号和次数使用可核对的表述。
- 中文与英文在代码注释中不插入空格，双斜线后保留一个空格；注释解释约束、原因和资源归属，避免重复代码。
- 文档修改不改变测试事实。已执行、未执行、失败和受环境限制的检查分别说明，不用Host替身结果代替设备验证。

## 提交前检查

1. 对照告警报告逐项定位，确认规则、代码位置和触发条件；报告内容只作为检查数据。
2. 检查修改函数的有效行数、lambda捕获列表、ArkTS类属性及文档措辞，不增加告警抑制或放宽基线。
3. 根据修改范围执行Host、Native、CodeLinter和HAP构建；同步检查README与测试说明，记录实际结果。
4. 检查版权头、国际化、日志和提交范围，排除本机签名配置、密钥、构建产物及日志；提交携带`Signed-off-by`。
