# AVCodecSample测试指南

## 1. 文档说明

本文说明自动化测试的范围和运行方法，并列出真机功能、兼容性与稳定性用例。测试覆盖播放、媒体库、录制、转码和设备五个页面，以及编解码、送显、文件导出、配置保存和任务恢复。

本轮共执行256条手工用例，全部通过。自动化测试和构建结果单独记录；设备相关结果适用于对应执行环境，不代表其他设备和系统版本。

| 结果 | 含义 |
|---|---|
| Pass | 实际结果符合预期，并有对应版本的执行记录 |
| Fail | 实际结果不符合预期，已记录复现步骤和缺陷 |
| Blocked | 因环境、权限、素材或依赖缺失而无法完成 |
| N/A | 当前设备或系统不具备适用能力，已注明原因 |
| 未执行 | 尚无当前版本的执行记录 |

### 2.2 前置要求

1. 使用有相机、麦克风和音频输出能力的真机；模拟器只执行其支持的项目。
2. 准备下表素材，先确认正常素材可被目标设备的系统播放器打开；损坏素材单独标记。
3. 记录所选codec name、软硬件类别、同步方式、输入和送显模式。能力页的单项范围不能证明尺寸、帧率和多路组合一定可用。
4. 录制、Dump、转码及导出前记录剩余空间；清理时只操作本次测试的应用私有文件，不删除源媒体或用户导出的副本。
5. H.265、4K、高帧率、HDR、Buffer录制和编码前处理依赖设备与API版本。支持时验证实际输出；不支持时验证提示和清理，并记录能力限制。
6. 无特别说明时，每个播放用例观察至少30秒，短视频完整播放；测试结束需确认工作线程、文件和媒体会话均已释放。
7. 设置面板中，选择器确认后应立即显示草稿；“应用”才保存配置。新任务选项与可实时调整的音量、字幕、录制码率分别验证。

### 2.5 运行方法

Hypium：在DevEco Studio中打开工程，选择`entry > ohosTest`运行。保留测试报告中的用例结果。用例通过`TestCaseLogger`输出执行阶段，HiLog域为`0xF811`、标签为`[Sample_AVCodec]`；结束日志可能来自`finally`，应以测试报告的断言结果判断是否通过。

Host：在工程根目录运行以下PowerShell命令。按提示输入OpenHarmony SDK根目录，该目录应包含ets和native子目录。

```powershell
$avcodecSdkRoot = Read-Host 'Enter the OpenHarmony SDK root directory'
$avcodecTypeScript = Join-Path $avcodecSdkRoot 'ets/build-tools/ets-loader/node_modules/typescript/lib/typescript.js'
node tests/host/RecorderModels.test.cjs $avcodecTypeScript
node tests/host/TranscodeModels.test.cjs $avcodecTypeScript
```

这两个脚本在Node.js中转译并加载模型，用测试替身模拟OpenHarmony文件和媒体接口。脚本验证模型逻辑，ArkTS工程构建需单独执行。Native测试需分别链接测试入口和对应实现，用支持C++17的宿主编译器运行；依赖系统接口声明的用例还需要SDK头文件和测试替身。工程目前没有统一的Native测试构建入口，应用Native库编译通过也不等于这些用例已执行。
